# План интеграции HelloWorld.rs

Согласованные продуктовые решения Q1–Q8, 2026-10-09. Первая версия адаптера реализована; публикация не выполнялась. Основание: [исследование живой выдачи и контракта core](helloworld-provider-research.md).

## Результат первой версии

Необязательный источник HelloWorld.rs в существующем `provider: ru-market`: поиск по настраиваемым фразам, чтение HTML-выдачи, нормализованные вакансии и объединение результатов запросов. Сохраняются вакансии Сербии, явно доступная из Сербии удалёнка и записи с неопределённой географией. Явно несовместимые ограничения учитываются только при наличии данных, а не по домену сайта или слову Remote.

Первая версия не загружает полные описания и не требует браузера. Общие фильтры по уровню и технологиям в core — [отдельный этап roadmap](roadmap/core-job-filters.md), который не блокирует выпуск адаптера. Текущий rank добавляет оценки и объяснения, но сам не исключает записи.

## Контракт данных

Использовать существующие поля Job: `title`, `company`, `url`, `sourceId`, `source`, `transport`, `location`, `locationText`, `locations`, `workArrangement`, `compensation`, `matchedQueries`, `dataLevel`, `hasDescription`, `note`.

- `source: helloworld-rs`, YAML-ключ `helloworld_rs`, `transport: html`.
- Ссылки: HTTPS на `www.helloworld.rs`, путь `/posao/<title>/<company>/<numeric-id>`, без query/fragment; идентичность объявления — источник и числовой ID.
- Сохранять исходную строку места. `Hibrid → hybrid`, `Rad od kuće / Remote → remote`. Город без явной метки режима не доказывает `onsite`; Remote не доказывает доступность из Сербии.
- Дата в выдаче — срок объявления; не записывать её в `postedAt`.
- Описания, которого нет в выдаче, не создавать из тегов: `hasDescription: false`, `dataLevel: listing`.
- Зарплата: разбирать подтверждённый формат `2.600,00`, сохранять валюту, net/gross и исходный текст. Неизвестный период — `unknown`; неоднозначные суммы сохранять текстом. Не использовать аналитику или зарплатные обзоры как зарплату вакансии.
- Неизвестные уровень, технологии или география сами по себе не исключают запись.

Предлагаемая техническая форма новых общих необязательных полей, реализующая согласованные списки:

```json
{
  "seniority": {
    "levels": ["mid", "senior"],
    "rawLabels": ["Intermediate", "Senior"]
  },
  "skills": ["Python", "SQL"]
}
```

Это иллюстрация контракта, а не утверждение о конкретной живой вакансии. Шкала: `intern / entry / mid / senior`; подтверждённые метки HelloWorld: `Junior → entry`, `Intermediate → mid`, `Senior → senior`. Сохранять все явно указанные уровни и технологии с удалением повторов. Не выводить навыки из названия должности. Если меток нет, соответствующее поле отсутствует; неизвестную метку уровня сохранять в `rawLabels`, без придуманного значения в `levels`. Исходные названия технологий сохраняются, словарь синонимов не требуется для первого адаптера.

- [x] Для включённого источника принимать явный непустой список запросов с текущими ограничениями списка строк; отклонять неподдерживаемые параметры. Health использует один явный проверочный запрос.
- [x] Сохранить старые `source: all` и порядки из 3/5/6 источников. Добавить новый источник в допустимый порядок без дубликатов, сохраняя стабильное дополнение пропущенных источников.

Предлагаемый пример после реализации:

```yaml
job_boards:
  - name: HelloWorld Serbia
    provider: ru-market
    ru_market:
      source: helloworld-rs
      max_pages: 2
      sources:
        helloworld_rs:
          enabled: true
          queries: [Python, Data Engineer]
```

Для одного источника достаточно существующего выбора `source`; общий селектор `market` из первоначального сербского плана остаётся возможным последующим расширением. Две страницы здесь — пример пользовательского лимита, а не новая глобальная настройка по умолчанию.

[Задача в roadmap](roadmap/core-job-filters.md) использует те же поля. Там определяются настройки отбора, приоритет явного уровня над эвристикой названия, правила нескольких значений и совместимость старых фильтров. Отсутствие данных пропускается; это уже согласованное требование.

## Известные ограничения источника

Публичная HTML-выдача технически проверена. В [исследовании](helloworld-provider-research.md) отдельно зафиксированы ограничения опубликованных условий и неполная проверка их текущей редакции; доступность HTML не означает подтверждённого разрешения площадки. План не предусматривает вход в аккаунт или обход CAPTCHA. Эти ограничения нужно сохранить в документации реализованного источника.

## Проверка реализации (2026-10-09)

- `npm test`: общие регрессии, getmatch, HelloWorld и provider smoke.
- `bash test/integration.sh`: isolated core checkout, plugin audit, fixture-backed
  `scan --dry-run` и запись в временный pipeline/history; пользовательские данные не менялись.
- Живой smoke адаптера: один запрос `q=Python`, одна страница, 30 вакансий,
  29 с технологиями, 30 с уровнями; остановка `page-limit`, без описаний и `postedAt`.
  Использован `node --use-system-ca` из-за сертификата сетевой среды, проверка TLS сохранена.
- Дополнительная живая проверка пустого поиска обнаружила 30 рекомендаций вместо
  совпадений: адаптер исключает их по подтверждённому zero-results heading/message.
- Реальные Intermediate + Senior найдены в keyword-снимке; multi-city остаётся
  синтетической проверкой и сохраняется одной неоднозначной строкой без выдуманного разделения.

Ограничения текущего core и условия площадки описаны в [docs/helloworld.md](helloworld.md).
