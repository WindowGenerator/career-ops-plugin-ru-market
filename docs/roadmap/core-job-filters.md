# Общие фильтры уровня и технологий в career-ops

Статус: запланировано отдельно от первого выпуска адаптера HelloWorld.rs. Решения согласованы 2026-10-09; фильтры core не реализованы. В 0.7.0 плагин и объединённый патч уже передают `employment` и `professional_role` через local-parser (проверено тестом `test/core-patch.mjs`); настройки допустимых и исключённых значений в core остаются невыполненными.

## Задача

Провайдеры передают явно указанные уровень и технологии вакансии в общих необязательных полях Job. Career-ops применяет пользовательские правила отбора к этим полям. Это расширение core для всех совместимых источников, а не специальная фильтрация внутри HelloWorld.

Текущие `skip_tiers` и `title_filter` читают название, а `content_filter` — описание. Они не используют отдельные метки уровня и технологий. Подтверждение и ограничения существующих потребителей: [исследование HelloWorld.rs](../research/helloworld.md). Контекст ревизии адаптеров, в которой добавлены поля `employment` и `professional_role`: [provider-architecture-review.md](provider-architecture-review.md).

## Принятые решения

- Отсутствие уровня или технологий не исключает вакансию: соответствующий новый фильтр пропускает её как запись с неизвестными данными. Известные поля по-прежнему проверяются, и другие фильтры продолжают действовать.
- Дальнейшая оценка пригодности остаётся задачей rank-пайплайна. Проверенный [rank-pipeline.mjs](../../../career-ops/rank-pipeline.mjs) добавляет оценки и объяснения, но не удаляет и не отфильтровывает строки. Последующий отбор — отдельный шаг; отсутствие метаданных не гарантирует отклонение на rank.
- Первый выпуск адаптера HelloWorld.rs не зависит от готовности этого этапа. До его реализации общие поля могут передаваться, но поддержка их фильтрации не заявляется.
- Существующее поведение фильтров и провайдеров сохраняется при отсутствии новых настроек.
- Явный уровень источника использует шкалу `intern / entry / mid / senior` с сохранением исходных меток. Для HelloWorld согласованы `Junior → entry`, `Intermediate → mid`, `Senior → senior`. Отсутствующий или нераспознанный уровень остаётся неизвестным; это отличается от текущего fallback классификатора заголовков в `mid`.
- Все явно указанные уровни и технологии передаются списками. Предложение формы полей `seniority.levels`, `seniority.rawLabels`, `skills` находится в [плане HelloWorld](helloworld-provider.md); правила фильтрации нескольких значений относятся к этому этапу.
- Добавляются необязательные поля Job `employment` и `professional_role` (решение ревизии адаптеров, раздел c). Плагин передаёт их сразу как дополнительные поля, как `dataLevel` и `eligibility`; core начинает их использовать только после реализации этого этапа. Форма, как у уровня и технологий: списки строк с сохранением исходных меток, например `employment: { values: [], rawLabels: [] }` и `professional_role: { values: [], rawLabels: [] }`. Точная форма уточняется на этапе реализации и фиксируется в `_types.js`.
- Контракт фильтрации новых полей совпадает с правилами выше: неизвестное значение не исключает вакансию, известное проверяется независимо от других полей, старые конфигурации не меняются. Для `employment` и `professional_role` core получает разрешённые и исключённые значения; сравнение идёт по нормализованным значениям, исходные метки остаются для отображения причин.
- Фильтры `experience`, `employment` и зарплата для HH применяются в core после выборки по полям Job, а не серверными параметрами; серверные параметры HH (`search_field`, `excluded_text`, `professional_role`, `only_with_salary`) ограничены браузерным companion. Основание — convention core: серверных фильтров в core-провайдерах нет.
- Все эти поля проходят через local-parser одним объединённым патчем core вместе с флагами инъекций и исправлением формы `salary`; патч применяется установщиком локально, обновления core могут потребовать его переустановки (решение g в [provider-architecture-review.md](provider-architecture-review.md)).
- Маршрут local-parser передаёт только перечисленные в нём ключи (`../career-ops/providers/local-parser.mjs:216-223`): для новых полей список нужно расширить, иначе они будут отброшены (как сейчас `skills` и `seniority`).

- [ ] Добавить настройки фильтрации в core: разрешённые/исключённые уровни и технологии. Согласовать правила совпадения нескольких значений и сочетания с существующими фильтрами.

Сделано в патче: `_types.js` и список ключей local-parser; не сделано: настройки фильтрации и причины исключения.

## Критерии готовности

1. Одна настройка core работает с одинаковыми структурированными данными от разных провайдеров.
2. Вакансия без уровня/технологий не исключается только из-за их отсутствия.
3. Неизвестное поле не отменяет проверку другого, известного поля.
4. Старые конфигурации сохраняют прежнее поведение.
5. Документация различает доступность метаданных и готовность их фильтрации.
6. Поля `employment` и `professional_role` проходят от провайдера и через local-parser до фильтров core; вакансия без этих полей не исключается.

Открытые решения отдельного этапа core: схема настроек, приоритет уровня из источника, правила фильтрации нескольких значений и сопоставления технологий. Представление уровней и технологий списками уже согласовано. Дополнительно открыта точная форма `employment` и `professional_role` и набор значений, которые HH companion сможет извлечь из выдачи.
